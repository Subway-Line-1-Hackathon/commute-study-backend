# R8 자료 삭제

`DELETE /api/materials/{id}`는 JWT가 필요하다. 본인 자료의 READY, FAILED, EXPIRED 상태에서 논리 삭제하고 204를 반환한다. 이미 삭제한 본인 자료도 204이며, UPLOADED 또는 PROCESSING은 409, 없는 자료나 타인 자료는 404다.

204는 삭제 표시와 Storage 객체별 정리 예약이 함께 DB에 커밋되었음을 뜻한다. 원본의 물리적 삭제 완료를 보장하지 않는다. 실패한 객체는 큐에 남아 재시도하며 PDF/PPTX 원본과 이미지 묶음의 모든 객체를 대상으로 한다. 운영 프로필에서 정리 스케줄러가 기본 활성화되며, 로컬에서는 기본 비활성화다. `MATERIAL_DELETION_CLEANUP_ENABLED`로 설정한다. 외부 AI에 이미 전송된 요청을 취소하지는 못하지만 삭제 후 늦은 결과 저장은 차단한다.

삭제 자료는 자료·단원 목록과 신규 학습 선택에서 제외한다. 기존 세션 및 학습 기록, 문제 해설과 오답노트 조회는 유지한다. 추출 원문 `material_page`도 유지되므로 보관 기간과 삭제 범위는 팀에서 별도 결정해야 한다. 회원 탈퇴 뒤에도 Storage 정리 큐의 객체 참조가 남을 수 있으므로 보관 및 개인정보 정책도 검토해야 한다.

## 배포 전 확인

- R7 PR #81의 V8이 먼저 병합·적용되어야 한다. V9를 먼저 적용한 뒤 V8을 추가하면 Flyway 순서 문제가 발생할 수 있다. 다른 미병합 작업의 마이그레이션 번호도 병합 전에 재확인한다.
- 구버전 서버는 `deleted_at`을 알지 못한다. 구버전 인스턴스가 삭제된 자료를 다시 노출하거나 처리하지 않도록 중지·전환 순서를 계획한다.
- R7과 `QuestionPregenService` 및 관련 테스트의 변경이 겹친다. 통합 시 비동기 처리와 삭제 경합을 함께 검증한다.
- 격리 PostgreSQL에서 V8 → V9 및 동시성·Storage 재시도를 검증한 후 배포한다. H2 테스트만으로 PostgreSQL 동작이 검증된 것은 아니다.
